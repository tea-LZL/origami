# Palette Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Richer, warmer color system: consolidated theme tokens, semantic status/role hues in real UI spots, a 12-hue tag palette, and a new warm dark "ember" theme — with AA contrast and forced-colors intact.

**Architecture:** CSS custom properties stay the single source of truth in `ui/src/app.css`. Theme duplication is removed by resolving `system` to a concrete theme attribute in JS. New hues are tokens first, then applied at existing semantic surfaces (folder roles, outbox/sync chips, tags). A small contrast script pins WCAG AA for every theme's text/surface pairs.

**Tech Stack:** Svelte 5 + TypeScript + vitest, plain CSS custom properties, node script for contrast checks.

**Spec:** `docs/superpowers/specs/2026-09-26-hardening-caching-palette-design.md` (Track C)

## Global Constraints

- No status conveyed by color alone — icon or label always present.
- `forced-colors` behavior unchanged (existing pip/tint rules still clear correctly).
- UI stays provider-neutral ([[backend-seam]]); themes are pure presentation tokens.
- WCAG AA (4.5:1 body text, 3:1 large/UI) for: `--fg`/`--bg`, `--fg`/`--bg-raised`, `--fg-muted`/`--bg`, `--accent-fg`/`--accent`, `--danger-fg`/`--danger`, `--tag-fg`/`--tag-*` in **every** theme.
- Existing hues preserved where already correct: `--success #256b52`, `--warning #93601c`, `--danger #aa3c4c` (light) unless a contrast check forces adjustment.
- Commits only when the executor is explicitly authorized to commit; otherwise leave the worktree dirty.

## Review Focus

- OS set to dark + app preference `light` must stay light after restart and after an OS scheme flip while running (`system_resolution_roundtrip`).
- Ember theme must not reuse navy surfaces — bg family is warm charcoal (`hsl` hue 25–40), not blue (`ember_surfaces_are_warm`).
- A tag named to hash into any of the 12 slots must render readable on both paper and dark surfaces (contrast script covers `--tag-fg` pairs).
- Outbox failed chip and folder role icons must remain distinguishable in `forced-colors` (icon/label text present — `semantic_surfaces_have_text`).
- Old saved preference value `"system"` and any unknown value must still load without throwing (`loadPreferences_unknown_theme_safe`).
